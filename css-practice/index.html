Variables

Define once, use everywhere. Great for theming.

SCSS
$primary: #6366f1;
$spacing-md: 16px;

.button {
  background: $primary;
  padding: $spacing-md;
}
→
Compiled CSS
.button {
  background: #6366f1;
  padding: 16px;
}

Nesting

Write child selectors inside their parent. Mirrors your HTML structure.

SCSS
.card {
  padding: 16px;

  .title {
    font-size: 18px;
  }

  .body {
    color: #555;
  }

  &:hover {
    box-shadow: 0 2px 8px rgba(0,0,0,0.1);
  }
}
→
Compiled CSS
.card {
  padding: 16px;
}

.card .title {
  font-size: 18px;
}

.card .body {
  color: #555;
}

.card:hover {
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
}

& refers to the parent selector. &:hover becomes .card:hover.

Mixins

Reusable chunks of CSS. Define once with @mixin, call with @include.

SCSS
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

@mixin grid-responsive($min: 200px) {
  display: grid;
  grid-template-columns:
    repeat(auto-fill, minmax($min, 1fr));
  gap: 16px;
}

.hero {
  @include flex-center;
}

.card-grid {
  @include grid-responsive(160px);
}
→
Compiled CSS
.hero {
  display: flex;
  align-items: center;
  justify-content: center;
}

.card-grid {
  display: grid;
  grid-template-columns:
    repeat(auto-fill, minmax(160px, 1fr));
  gap: 16px;
}

Mixins can accept arguments — $min above defaults to 200px but can be overridden per call.

Partials & @use

Split CSS into multiple files. Underscore prefix = not compiled on its own.

_variables.scss
$primary: #6366f1;
$danger: #ef4444;
$spacing-sm: 8px;
$spacing-md: 16px;
styles.scss
@use './variables' as *;

.button {
  background: $primary;
  padding: $spacing-md;
}

.error {
  color: $danger;
}

@use is the modern way. @import is deprecated but common in older codebases.
In Angular, you'll typically see a _variables.scss or _theme.scss imported into styles.scss and component stylesheets.

Single source of truth

Never hardcode the same value in two places. If it changes, it should change in one spot.

Spacing scale — no magic numbers

Pick a scale and never deviate. Common scale: 4, 8, 12, 16, 24, 32, 48, 64px. Never write padding: 13px.

Don't fight the flow

If you're reaching for position: absolute or negative margins to fix a layout, the layout structure is probably wrong. Fix that first.

Bad — fighting flow
.sidebar {
  position: absolute;
  top: 64px;
  left: 0;
  /* now everything else
     needs manual offset */
}
→
Good — use the layout
.layout {
  display: grid;
  grid-template-columns:
    200px 1fr;
  grid-template-areas:
    "sidebar content";
}

Avoid deep specificity

Deep selectors are fragile and hard to override. Flat class names beat deep nesting.

Bad
.card .body .section .title span {
  font-size: 14px;
  /* needs this exact chain
     to ever override */
}
→
Good
.card-title {
  font-size: 14px;
  /* one class, easy
     to override anywhere */
}

Never use IDs for styling

IDs have very high specificity — they beat any class selector and are painful to override. Classes only.

Bad
#submit-button {
  background: #6366f1;
}
→
Good
.btn-primary {
  background: #6366f1;
}

Mixins for repeated patterns

Don't copy-paste the same 3 lines of flex/grid setup. Extract it.

_mixins.scss
@mixin flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

@mixin flex-between {
  display: flex;
  align-items: center;
  justify-content: space-between;
}

@mixin responsive-grid($min: 200px) {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax($min, 1fr));
  gap: $spacing-md;
}

// Usage:
.hero       { @include flex-center; }
.navbar     { @include flex-between; }
.card-grid  { @include responsive-grid(160px); }

Keep nesting shallow — max 3 levels

Deeper nesting compiles to overly specific selectors that are hard to override.

Bad — 4 levels deep
.card {
  .body {
    .section {
      .title {
        font-size: 14px;
        // compiles to:
        // .card .body .section .title
      }
    }
  }
}
→
Good — max 2 levels
.card {
  .title { font-size: 14px; }
  &:hover { box-shadow: ...; }
}

// compiles to:
// .card .title
// .card:hover

One partial per concern

Split your SCSS into focused files. styles.scss is just a list of @use statements.

File structure
styles/
  _tokens.scss      ← all variables (colors, spacing, fonts)
  _reset.scss       ← box-sizing, margin reset
  _typography.scss  ← font sizes, line heights, headings
  _mixins.scss      ← reusable flex/grid/media query patterns
  _components.scss  ← card, button, badge, form etc
  styles.scss       ← only @use statements, nothing else

In Angular: global styles/ folder for this. Per-component .scss files for component-specific styles only.

The overarching principle

CSS is easy to write and hard to maintain. Every decision should make future changes cheaper, not just make today's thing work.
